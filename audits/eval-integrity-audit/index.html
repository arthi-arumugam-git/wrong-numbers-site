( Who it's for )

Who this
is for.

For teams whose model choices, launches or safety claims rest on an eval score, whether it comes from inspect_evals, lm-evaluation-harness, TruLens, deepeval or a harness built in-house.

Eval bugs rarely crash. A metric with nothing to score reports 0.0, a judge's restated scale is read as its rating, a truncated answer is graded as complete. The run finishes, the dashboard fills in, and the number is wrong. The audit looks for exactly that: the value stays plausible and nothing raises.

( What I check )

Six places
the number goes wrong.

  1. 01

    Empty and mismatched denominators

    What each metric returns when nothing was scored, and whether its numerator and denominator count the same samples. A metric with no samples should report nan or raise, not 0.0.

  2. 02

    LLM-as-judge parsing

    Whether the judge's verdict is what gets read, rather than a number from the rubric or the stated scale, and what happens when a rating fails to parse.

  3. 03

    Truncated output

    Whether a generation cut off mid-reasoning, inside an unterminated block, is scored as the model's answer instead of as unanswered.

  4. 04

    Ground truth and sample counts

    Whether rows are matched to the right labels, whether scores depend on iteration order, and whether reported counts reflect what was actually evaluated.

  5. 05

    Schema defaults in tool calls

    For function-calling evals, whether an optional parameter stated at its own default is scored as a disagreement.

  6. 06

    Tokens and cost per run

    Whether the usage and spend your eval reports for each run match what the provider actually billed.

What does an LLM eval integrity audit check?

The code that turns model outputs into scores: metrics and their denominators, LLM-as-judge parsing, handling of truncated output, ground-truth alignment, sample counts and per-run token accounting. Each one gets the same question: when this goes wrong, does anything raise, or does a plausible number come out?

Which eval frameworks do you work with?

inspect_evals, lm-evaluation-harness and TruLens, where I have merged fixes upstream, and others such as deepeval, lighteval and harnesses built in-house. The audit reads your code and the framework code it relies on.

Why would my eval score read 0.0 instead of failing?

Usually an empty denominator: a metric that measured nothing returns its starting value instead of nan. 0.0 is indistinguishable from a model that got everything wrong, so the run looks complete. Reporting nan, or raising, makes the problem visible.
