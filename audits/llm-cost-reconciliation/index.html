Who this

For teams whose dashboards, cost reports or per-customer margins are built from the token counts their own code records, and whose invoice from Anthropic, OpenAI, Bedrock or Gemini doesn't match.

The recurring finding across my merged upstream fixes: the counts look right, the dollars are wrong, and nothing raises. Cached tokens are the most common cause I have fixed, but stale price tables, streaming code and retries each produce the same quiet gap.

( What I check )

Six places
the number goes wrong.

  1. 01

    Provider adapters

    Every provider adapter in your path, and whether it reads the usage object whole or drops fields on the way.

  2. 02

    Cache-token conventions

    Anthropic reports cache reads and writes outside input_tokens; OpenAI-style prompt counts include them. Mixing the two conventions under- or double-counts every cached request.

  3. 03

    Streaming paths

    Whether accumulated usage survives the stream, or is overwritten by the final message_delta and loses its input side.

  4. 04

    Prices and retries

    Stale or missing price tables, unreachable pricing tiers, calls priced under the wrong provider, and retries that are billed but never logged.

  5. 05

    Telemetry

    OpenTelemetry spans and observability exports, so usage reaches the dashboard with the numbers it left with.

  6. 06

    The reconciliation itself

    Your recorded usage for one window, set against the provider's own usage report and invoice for the same window, then split until the gap is explained.

Why is my Anthropic bill higher than my dashboard?

Most often, cached tokens. Anthropic reports cache_read_input_tokens and cache_creation_input_tokens separately from input_tokens, and code that sums only input and output tokens silently leaves cache activity out. The other recurring causes are a stale price table, streaming code that overwrites accumulated usage with the final message_delta, and retries that are billed but not logged.

What do you reconcile against?

The provider's own usage report and invoice for the same window as your recorded usage. Differences can come from scope, timing or discounts as well as defects, so the gap is split by cache-hit rate, model, streaming and error rate until each part is explained.

Can I check my own stack first?

Yes. Send one request with a known cache hit and compare what your metering recorded, what the provider's usage object returned, and what the provider's cost report shows. billproof runs that comparison for Claude Code, Codex and Gemini CLI transcripts.
