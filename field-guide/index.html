( The field guide )

Thirteen ways an LLM number goes wrongwithout raising

A field guide to one defect class in LLM eval, tracing and cost libraries: a number comes out wrong and nothing raises. Each shape below says what goes wrong and how to catch it in your own code.

( Where it comes from )

31 write-ups,
13 shapes.

The guide is drawn from 31 long-form write-ups, each reproduced against an installed package, behind pull requests in libraries such as inspect_evals, TruLens, lm-evaluation-harness, Pydantic Logfire, LiveKit and Pipecat.

The headline result is not any single bug. The same few shapes recur across codebases that share no code, which means each one can be caught by pattern rather than by luck.

The full write-ups, with the real numbers and links to every fix, are on GitHub.

01

Cache-token exclusion

A provider reports its input token count net of the prompt cache and bills the cache counters separately on top. The library maps that net count straight onto prompt_tokens and builds totals from it, so every token served from cache disappears from the accounting.

( How to catch it )

Grep for input_tokens, inputTokens or prompt_tokens assigned from a provider response with no cache-read or cache-write term nearby. Then build a usage object where the cached portion dwarfs the fresh one, say input_tokens=3, cache_read_input_tokens=20000, and assert the reported count equals the billed count.

Found in: Six frameworks: Pipecat, LiveKit, LlamaIndex, Haystack, mcp-use and CrewAI, each an independent implementation of the same arithmetic.

02

A guard that filters a legal value

A truthiness or type check meant to skip missing data instead filters a legal value, such as 0, an integer cost or a dict, and a default or nothing at all takes its place.

( How to catch it )

Grep for if value: and if ... else guards over numeric fields, isinstance(..., float) on money, and hasattr on objects that can arrive as dicts. A truthiness guard on a required field can only ever filter a legal value. Feed it 0, 0.0, an integer and a dict.

Found in: Three libraries.

03

Silent-zero metrics

A metric path that failed, or had nothing to score, emits a number on the metric's own scale instead of failing, and that number is indistinguishable from a real judgement.

( How to catch it )

Grep metric bodies for else 0.0, return 0 and divisors forced to 1 on empty input. Feed a run where every sample failed to parse and a run where the model legitimately declined, and assert the two are distinguishable, ideally with the empty case returning nan or raising.

Found in: Two libraries.

04

A denominator that does not match what was counted

The numerator is computed over a filtered or truncated set and the denominator over the original one, so the reported mean is scaled by a ratio nobody chose.

( How to catch it )

Grep for divisions where the numerator mentions filter, isinstance, a slice or a comprehension with an if, and the denominator is a bare len(). Score a list containing Nones and assert a perfect run reports 1.0, and that an all-empty run raises.

Found in: Two libraries.

05

The fix lands on some twins and not others

Near-identical sibling implementations of one contract exist, a fix or feature lands on some of them, and the siblings quietly disagree from then on.

( How to catch it )

When a fix lands, grep the rest of the repository for the exact line it replaced; the sibling still carrying it is the finding. Diff files that share a naming pattern, such as precision.py, recall.py and f1_score.py, and pin them with an invariant test across siblings.

Found in: Four libraries.

06

A schema default scored as a disagreement

The scorer holds the function schema but never reads parameter defaults, so an optional parameter stated at its own default and the same parameter omitted are scored as disagreeing, in both directions.

( How to catch it )

Test the pair: ground truth omits the parameter and the model states the default, then the reverse. Both must score as agreement, and a non-default value must still fail.

Found in: One library.

07

Truncation scored as the answer

A generation that stops inside an unterminated block is scored as if the truncated reasoning were the model's answer.

( How to catch it )

Feed the scorer a generation cut off mid-reasoning, inside an unterminated tag or fence, and assert it is scored as unanswered rather than as whatever string the truncation left behind.

Found in: One library.

08

Aggregate written where the per-sample value belongs

A per-sample field is computed from a dataset-wide accumulator, so every sample's value drifts toward the running mean and depends on iteration order.

( How to catch it )

Grep for += on a matrix or counter followed by a per-sample assignment that references the accumulated name. Then evaluate the same data forward and reversed and assert every sample keeps its score.

Found in: One library.

09

Pricing tiers unreachable or mis-modeled

Multi-tier pricing exists in the data, and the code that selects a tier either cannot reach the higher tiers, applies the wrong tier-selection model, or never carries the tier data to the consumer at all.

( How to catch it )

For every model with more than one published tier, price one request above the threshold and compare against the provider's own bill. Check what the default branch of a tier switch actually selects.

Found in: Three libraries.

10

Missing price data, and cost silently dropped

The price for a real model is absent, or the cost lookup fails, and an exception handler or a skip turns that into a span with token counts and an empty cost column.

( How to catch it )

Assert that every model name the SDK advertises resolves a price, and count cost assertions per integration test file; a provider with none is where the gap hides.

Found in: Two libraries.

11

Config accepted and silently ignored

A parameter exists on the public signature, is accepted without complaint and is never wired to anything, so setting it does nothing, and its absence can even remove a protection the underlying library would have provided.

( How to catch it )

For every constructor and function parameter, grep for a use beyond the signature; a parameter read zero times is the finding. Pass a non-default value and assert observable behaviour changes.

Found in: One library.

12

A merge or copy that drops or corrupts usage

Code that merges, accumulates or copies usage objects encodes its own assumption about the provider's stream semantics or the model's field list, and silently loses or inflates counters when that assumption is wrong.

( How to catch it )

Replay a recorded stream through both the library's accumulator and the vendor SDK's, and diff the results. Assert the output value itself, not only that input + output == total, which can hold while the output is wrong.

Found in: Three libraries.

13

The same silence, somewhere other than a number

The same failure mode in different clothes: a code path produces something well-formed and plausible, hands it to a caller with no way to tell, and never says a word. The artifact is a message, a trace tree or a file rather than a float.

( How to catch it )

Write parity tests between streamed and non-streamed paths: the same request with stream=true and stream=false must produce the same tool calls. For files, assert exact bytes rather than parsed content.

Found in: Three libraries.
